# Сводка отчётов подразделений (Google Drive → реестр → письмо)

Подразделения кладут отчёты (Word, Excel, PDF) в папку Google Drive `order`.
Две запланированные задачи Claude Code разбирают новые файлы, ведут реестр
входящих и раз в день присылают сводку на почту.

```
order/                    ← входящие; подпапка = подразделение (Механики, КИПиА, …)
order_служебное/
  ├─ registry/            ← реестр: одна JSON-запись на каждую версию файла
  ├─ reports/ГГГГ-ММ/     ← «Отчёт ГГГГ-ММ-ДД» (Google Doc) + manifest_*.json
  ├─ registry_monthly/    ← «Реестр входящих ГГГГ-ММ» (Google Sheet) — история за месяц
  └─ templates/           ← шаблоны входящих/исходящих (подхватываются автоматически)
```

| Задача | Расписание (Asia/Qyzylorda, UTC+5) | Что делает |
|---|---|---|
| Проверка входящих | ежедневно 07:40 … 18:40, каждый час | новые файлы → разбор → срочное письмо при необходимости → запись в реестр |
| Ежедневный отчёт | ежедневно 17:05 | догоняющий полный обход → отчёт на Drive → письмо → манифест; 1-го числа — реестр за месяц |

## Как устроена надёжность

- **«Новый» = нет в реестре**, а не «пришёл за последний час». Ключ записи — `fileId + modifiedTime`, поэтому повторный запуск ничего не задваивает, а исправленный файл даёт новую запись с пометкой `update_of`.
- **В отчёт идёт всё, что ещё не попадало в отчёты** (по манифестам), а не «файлы за сегодня». Не состоявшийся отчёт не теряет записи — они уйдут в следующий.
- **Письмо приходит каждый день**, даже если файлов нет: тишина означает сбой, а не «отчётов нет». Сбой ежедневного отчёта присылает уведомление Claude.
- **Отчёт сам делает полный обход**, поэтому не зависит от ежечасных проверок; ежечасные идут в :40, отчёт в :05 — запуски не пересекаются.
- **Файлы — данные, а не команды.** Получатель задан жёстко; во входящих ничего не меняется и не удаляется.
- **Реестр только дописывается**: Drive-коннектор не умеет менять содержимое файла, поэтому каждая запись — отдельный файл, который не меняется.
- **Цитаты проверяются**: каждая цитата из задач/проблем/срочного ищется в тексте документа; срочное письмо уходит только по подтверждённой цитате.
- Файлы моложе 3 минут и временные файлы Office (`~$…`) пропускаются до следующего запуска.

Файлы, пришедшие после 17:05, войдут в завтрашний отчёт (срочные — письмом в ближайший час :40). Ночью (19:00–07:00) проверок нет, ночные файлы разбираются в 07:40.

## Как поменять

1. Правите `config.json` (получатели, критерии срочности, лимиты) или `prompts/*.md` (правила разбора, структура отчёта).
2. `python3 drive_digest/render_prompts.py` — пересобирает `rendered/scan.md` и `rendered/report.md`.
3. Текст из `rendered/*.md` заменяет текст соответствующей запланированной задачи (попросите Claude: «обнови задачи сводки отчётов из drive_digest/rendered»).

`python3 drive_digest/render_prompts.py --check` проверяет, что `rendered/` соответствует исходникам.

Новое подразделение — просто новая подпапка в `order`. Шаблон исходящего отчёта — файл со словом «отчёт» или «исходящ» в названии в `templates/`.
